# ADR-002 (Task5). IAM: единый вход (SSO), ролевой доступ и таблица ролей

## Общая информация

1. **Родительский артефакт** - `ADR-001-tenant-isolation.md`, условие Задания 5 (IAM, ролевой
   доступ и SSO).
2. **Автор ADR** - Анзор Березгов, архитектор.
3. **Статус** - Принят.

## Контекст

У платформы много участников: сотрудники "GoFuture", сотрудники партнёров (тенантов),
интеграционные сервисы партнёров, а также пассажиры и водители. Нужна единая система
идентификации с **единым входом (SSO)**, **ролевым доступом** и привязкой к тенанту, чтобы
никто не видел чужие данные.

## Требования

| No. | Требование |
|---|---|
| 1 | Единый вход (SSO) для пользователей партнёров и платформы. |
| 2 | Ролевой доступ с принципом минимально необходимых прав. |
| 3 | Все права ограничены рамками тенанта. |
| 4 | Отдельная аутентификация для интеграций (ключи/токены). |
| 5 | Централизованное управление секретами и токенами. |
| 6 | Аудит доступа к данным тенантов. |

## Решение

### Компоненты IAM

| Компонент | Роль |
|---|---|
| **Единая система идентификации** | аутентификация, выпуск токенов, единый вход (SSO). Протокол - OIDC. |
| **Ролевая модель (RBAC)** | роли и права; проверка прав на каждом запросе. |
| **Привязка к тенанту** | каждая учетная запись и роль относятся к конкретному тенанту (кроме платформенных). |
| **Интеграционные ключи** | отдельные учетные данные для сервисов партнёров. |
| **Секрет-хранилище** | хранение и ротация секретов и ключей (см. Task3/ADR-006). |
| **Аудит доступа** | неизменяемый журнал входов и доступа к данным. |

### Как работает доступ

1. Пользователь входит через **единый вход** (SSO) и получает токен.
2. В токене зафиксированы идентификатор пользователя, **тенант** и **роли**.
3. Шлюз проверяет токен и передаёт контекст тенанта дальше; подменить тенант из клиента нельзя.
4. Каждый сервис проверяет права на операцию (RBAC) и обращается только к данным своего тенанта.
5. Интеграции партнёров используют ключи, ограниченные их тенантом.

### Таблица ролей и уровней доступа

| Роль | Кто это | Область | Уровень доступа к данным |
|---|---|---|---|
| **Администратор платформы** | сотрудник "GoFuture" | вся платформа | настройки платформы; **без доступа к персональным данным тенантов** |
| **Администратор тенанта** | сотрудник партнёра | свой тенант | полный доступ к данным своего тенанта, управление ролями и конфигурацией |
| **Оператор поддержки тенанта** | сотрудник партнёра | свой тенант | данные своего тенанта, ограниченный набор полей |
| **Аналитик тенанта** | сотрудник партнёра | свой тенант | обезличенные агрегаты своего тенанта; без персональных данных |
| **Бухгалтер тенанта** | сотрудник партнёра | свой тенант | финансовые данные своего тенанта |
| **Интеграционный сервис** | система партнёра | свой тенант | только свои данные по API, в рамках выданных прав |
| **Водитель** | пользователь партнёра | свой тенант | только свои данные |
| **Пассажир** | пользователь партнёра | свой тенант | только свои данные |

Правило: **платформенные роли не видят персональные данные тенантов**, а роли тенанта не видят
данные других тенантов.

### Единый вход (SSO)

- Партнёр может подключить свой корпоративный вход (федерацию) к единой системе идентификации.
- Пользователи партнёра входят один раз и получают доступ к своим приложениям.
- Выход и отзыв доступа централизованы.

## Альтернативы

| Альтернатива | Преимущества | Недостатки | Вердикт |
|---|---|---|---|
| Единая система идентификации + RBAC + SSO (выбрано) | централизованно, безопасно | единая точка, нужна отказоустойчивость | Принято |
| Отдельная система входа на каждого тенанта | изоляция | дублирование, сложно поддерживать | Отклонено |
| Права только в коде приложения | простота | сложно менять, риск ошибок | Отклонено |
| Общие роли без привязки к тенанту | простота | риск доступа к чужим данным | Отклонено |

## Недостатки, ограничения и риски

- **Единая система идентификации - критичный компонент**: её отказ блокирует вход; митигируется
  отказоустойчивым развёртыванием.
- **Сложность ролей**: при росте числа тенантов и функций роли нужно ревизовать; вводится
  регулярный аудит прав.
- **Федерация с партнёрами** требует согласования форматов и настройки; часть партнёров может
  использовать локальные учетные записи.
- **Ошибка в проверке прав** - риск утечки; обязательны тесты изоляции и аудит доступа.
