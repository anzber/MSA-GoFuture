# Task 5. Мультитенантная платформа "GoFuture"

Родительские артефакты: [`../Task1/`](../Task1/), [`../Task2/`](../Task2/),
[`../Task3/`](../Task3/), [`../Task4/`](../Task4/).

## 1. Контекст

"GoFuture" хочет быстро запускать решения для партнёров в новых регионах: с полной изоляцией
данных между партнёрами и кастомизацией функциональности. Партнёры - локальные службы такси,
банки, e-commerce и другие. Нужна мультитенантная платформа: модель изоляции данных,
IAM-система с ролевым доступом и единым входом (SSO), автоматизированный онбординг партнёров
и мониторинг мультитенантного окружения.

## 3. Решение на одном экране

1. **Изоляция данных** - по умолчанию **отдельная БД на тенанта** в его регионе (физическое
   разделение), для регулируемых и особо крупных партнёров - **отдельный инстанс/кластер**;
   **схема на тенанта** - только исключение для очень мелких. Данные шифруются отдельным
   ключом на тенанта (KMS). Смешения данных нет.
2. **IAM** - единая система идентификации: единый вход (SSO), роли и права, ключи для
   интеграций. Роли ограничены рамками тенанта; платформенные роли не имеют доступа
   к персональным данным партнёров.
3. **Онбординг** - автоматизированный процесс: заявка -> создание тенанта (выделение ресурсов
   хранилища, конфигурации, лимитов) -> настройка доступа и SSO -> подключение интеграций ->
   проверки изоляции -> активация -> мониторинг.
4. **Мониторинг** - общий слой мониторинга + отдельные дашборды по каждому тенанту:
   нагрузка, ошибки, отставание обработки, использование квот; алерты и цели по каждому тенанту.
5. **Кастомизация** - конфигурация и флаги функций на тенанта (тарифы, зоны, способы оплаты),
   без изменения общего кода.

## 4. Ключевые компромиссы

| Решение | Почему | Компромисс/риск |
|---|---|---|
| Отдельная БД на тенанта + отдельный инстанс для регулируемых | физическая изоляция по умолчанию, проще комплаенс | дороже в эксплуатации при росте числа тенантов |
| Общий слой сервисов для всех тенантов | экономия и скорость запуска | риск "шумного соседа", нужны квоты |
| Роли в рамках тенанта | безопасность и локальные требования | больше сущностей доступа |
| Автоматизированный онбординг | скорость запуска партнёров | сложность выделения ресурсов и проверок |
| Кастомизация через конфигурацию, а не код | одинаковый код для всех | часть особых требований не покрыть |
