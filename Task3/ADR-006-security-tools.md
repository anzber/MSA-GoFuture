# ADR-006 (Task3). Доработка C2: инструменты защиты и обоснование

## Общая информация

1. **Родительский артефакт** - `Task1/ADR-004-tobe-c2-services.md` (C2 To-Be), условие Задания 3
   (WAF, Firewall и аналогичные).
2. **Артефакт** - [`C2_Global_Security.puml`](C2_Global_Security.puml) / `.png` (изменения красным).
3. **Автор ADR** - Анзор Березгов, архитектор.
4. **Статус** - Принят.

## Контекст

В ландшафт добавляются инструменты защиты периметра и внутренней сети. Их надо отразить на
диаграмме C2 и объяснить выбор. Все новые элементы и связи на диаграмме выделены **красным**.

## Требования

| No. | Требование |
|---|---|
| 1 | Защита внешнего периметра (веб-атаки, всплески трафика). |
| 2 | Сегментация внутренней сети и правила между сервисами. |
| 3 | Защита трафика между сервисами. |
| 4 | Управление секретами и аудит доступа. |
| 5 | Централизованный сбор событий безопасности. |
| 6 | Все изменения выделены на C2 красным. |

## Решение

### Добавляемые инструменты и механизмы

| Инструмент/механизм | Где размещается | Зачем |
|---|---|---|
| **WAF** | на входе каждого региона, перед балансировщиком | фильтрация веб-атак, защита API |
| **Защита от DDoS** | на периметре, перед WAF | отражение всплесков трафика и атак на доступность |
| **Firewall (сегментация сети)** | внутри региона, между зонами и сервисами | ограничение сетевого доступа по принципу минимально необходимого |
| **Ограничение частоты запросов** | на API Gateway | защита от злоупотреблений и перегрузки |
| **mTLS (взаимная TLS-аутентификация)** | между сервисами | подтверждение подлинности и шифрование внутреннего трафика |
| **IPS/IDS** | на периметре и внутри сети | обнаружение и предотвращение вторжений |
| **Секрет-хранилище** | платформенный слой | хранение и ротация секретов, отсутствие секретов в коде |
| **Централизованный сбор событий безопасности** | общий слой мониторинга | аудит и корреляция событий безопасности |

### Обоснование

- **WAF и защита от DDoS** обязательны на внешнем периметре: сервис доступен из интернета,
  и без фильтрации веб-атак и защиты от всплесков нельзя обеспечить целевые 99,99 %.
- **Firewall и сегментация** ограничивают "горизонтальное" движение внутри сети: даже при
  компрометации одного сервиса он не должен свободно обращаться к чужим данным.
- **mTLS** закрывает доверие между сервисами: внутренний трафик тоже шифруется и
  аутентифицируется, что важно для распределённой системы.
- **IPS/IDS** дают обнаружение вторжений, а централизованный сбор событий безопасности -
  возможность расследовать инциденты.
- **Ограничение частоты запросов** на API Gateway защищает от перегрузки и злоупотреблений
  (совпадает с требованием устойчивости из Task1).
- **Секрет-хранилище** убирает секреты из кода и конфигураций, обеспечивает ротацию.

### Размещение на диаграмме

На `C2_Global_Security.puml` (все изменения красным):
- перед каждым регионом - защита от DDoS и WAF;
- внутри региона - Firewall и сегментация, IPS/IDS, API Gateway с ограничением частоты;
- между сервисами - mTLS;
- в платформенном слое - секрет-хранилище;
- в мониторинге - централизованный сбор событий безопасности.

### Связь с другими решениями

- Защита периметра дополняет геомаршрутизацию (ADR-003) и аварийное переключение (ADR-004):
  при отказе регион исключается из маршрутизации, но защита действует в каждом регионе.
- Локальные требования (ADR-005) влияют на размещение данных, но не на инструменты защиты.

## Альтернативы

| Альтернатива | Преимущества | Недостатки | Вердикт |
|---|---|---|---|
| WAF + Firewall + DDoS + mTLS + IPS/IDS + секрет-хранилище (выбрано) | полное покрытие периметра и внутренней сети | несколько инструментов | Принято |
| Только WAF на периметре | простота | нет защиты внутренней сети и трафика между сервисами | Недостаточно |
| Защита только на уровне приложения | нет доп. инфраструктуры | слабее против сетевых атак и злоупотреблений | Отклонено |
| Единый "защитный шлюз" для всего | централизация | единая точка отказа, рост задержки | Отклонено |

## Недостатки, ограничения и риски

- **Дополнительная задержка** от проверок на периметре; митигируется размещением защиты
  в каждом регионе.
- **Сложность правил Firewall** при росте числа сервисов; митигируется шаблонами и ревью.
- **Ложные срабатывания IPS/IDS** могут блокировать легитимный трафик; нужна настройка и режим
  наблюдения перед блокировкой.
- **Стоимость** инструментов и их эксплуатации; часть уже есть в лендскейпе, остальное - по мере
  необходимости.
