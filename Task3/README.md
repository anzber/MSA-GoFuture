# Task 3. Обеспечиваем высокую нагрузку и глобальное развёртывание "GoFuture"

Родительские артефакты: [`../Task1/`](../Task1/) (C2 To-Be) и [`../Task2/`](../Task2/) (событийная
платформа). 

## Глоссарий

- **Юрисдикция (страна)** - правовая граница хранения персональных данных (RU / ID / BR / SG).
  В именах топиков `<jurisdiction>` = код юрисдикции, а поле `region` в конверте - тот же код (для совместимости со схемой).
- **Регион развёртывания** - географическая площадка провайдера. Каждая юрисдикция содержит
  не менее двух регионов развёртывания (Регион 1 - основной, Регион 2 - второй); исключение -
  город-государство (Сингапур), у которого регион один (см. ниже).
- **Зона (площадка)** - независимая зона/ЦОД внутри региона развёртывания.

## 1. Контекст

От "GoFuture" требуется **99,99 % доступности** и **низкая задержка** для пользователей
в Юго-Восточной Азии и Южной Америке. Это достигается развёртыванием **в более чем трёх
географических регионах**.

## 3. Решение на одном экране

1. **Юрисдикции и регионы:** 4 юрисдикции / 7 регионов развёртывания. У РФ, Индонезии и Бразилии -
   по два региона (Регион 1 + Регион 2); у Сингапура - единственный регион (исключение).
2. **Развёртывание:** каждая юрисдикция обслуживается **двумя регионами внутри страны**
   (active-active по обслуживанию, запись - primary + синхронный standby; плюс свидетель
   кворума); персональные данные хранятся в стране пользователя и синхронно реплицируются
   между её регионами, но не покидают страну. Между разными юрисдикциями идут только
   справочные данные и обезличенные агрегаты.
3. **Геомаршрутизация:** глобальный DNS с учётом географии и задержки направляет пользователя
   в ближайший здоровый регион; для регулируемых данных маршрут принудительно в домашнюю
   юрисдикцию пользователя.
4. **Аварийное переключение:** отказ зоны - внутри региона; отказ региона - переключение
   трафика и записи на второй регион той же юрисдикции (синхронная реплика, RPO=0); полная
   потеря юрисдикции - катастрофа, восстановление из резервных копий (согласуется). Таблица
   сценариев с точками отказа.
5. **Защита:** WAF, Firewall (сегментация), защита от DDoS, mTLS между сервисами, IPS/IDS,
   секрет-хранилище, централизованный сбор событий безопасности; всё выделено на C2 красным.
6. **Комплаенс:** локальное хранение данных, локальные платёжные провайдеры, аудит, согласия,
   сроки хранения и запрет трансграничной передачи персональных данных.

## 4. Ключевые компромиссы

| Решение | Почему | Компромисс/риск |
|---|---|---|
| 4 юрисдикции / 7 регионов развёртывания с локальным хранением | низкая задержка + локальные требования + отказ региона | дороже, сложнее эксплуатация |
| Репликация ПД только внутри юрисдикции (между её регионами); между странами - справочники и агрегаты | соблюдение локального хранения | нет глобального "единого" состояния пользовательских данных |
| Геомаршрутизация на уровне DNS | простота и независимость от приложений | задержка обновления маршрутов при отказе |
| Два региона на юрисдикцию (active-active по обслуживанию, primary/standby по записи) + witness | отказ региона без потери данных (RPO=0) | задержка записи >= 1 RTT (5-15 мс в городе, 20-40 мс между регионами), нужен кворум |
