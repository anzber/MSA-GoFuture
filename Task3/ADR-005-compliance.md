# ADR-005 (Task3). Стратегия комплаенса

## Общая информация

1. **Родительский артефакт** - `ADR-001..ADR-004`, условие Задания 3 (локальные регуляторные
   требования).
2. **Автор ADR** - Анзор Березгов, архитектор.
3. **Статус** - Принят.

## Контекст

Компания работает в нескольких странах, и каждая страна предъявляет свои требования к обработке
персональных данных: где их можно хранить, можно ли вывозить, как долго хранить, как обеспечивать
доступ и аудит. Эти требования напрямую влияют на архитектуру: они определяют, где размещаются
данные и какие операции можно выполнять в чужом регионе.

## Требования

| No. | Требование |
|---|---|
| 1 | Персональные данные резидентов хранятся в их стране/регионе. |
| 2 | Трансграничная передача персональных данных ограничена или запрещена. |
| 3 | Интеграция с локальными платёжными и картографическими сервисами. |
| 4 | Аудит доступа к персональным и финансовым данным. |
| 5 | Управление согласиями и сроками хранения, право на удаление. |
| 6 | Разграничение доступа и защита данных при хранении и передаче. |

## Решение

### Локальные требования по регионам

Общий принцип: **персональные данные остаются в стране пользователя**; между регионами
передаются только справочные данные и обезличенные агрегаты (см. ADR-002).

### Мероприятия комплаенса

1. **Локальное хранение.** Архитектурно закреплено: домашний регион пользователя хранит его
   персональные данные; маршрутизация направляет операции с ними только туда (ADR-003).
2. **Локальные платёжные и картографические сервисы.** Интеграции подключаются через слой
   изоляции интеграций для каждого региона; договоры с локальными провайдерами.
3. **Управление согласиями.** Согласие на обработку хранится в домашнем регионе; предусмотрены
   отзыв согласия и удаление данных.
4. **Сроки хранения и удаление.** Для персональных данных - минимально необходимые сроки;
   для финансовых и аудиторских - установленные законом сроки; по истечении данные удаляются.
5. **Аудит доступа.** Неизменяемый журнал доступа к персональным и финансовым данным; только
   уполномоченные роли.
6. **Защита данных.** Шифрование при хранении и передаче; маскирование персональных данных
   в логах; разграничение доступа по ролям.
7. **Запрет вывоза.** Технически исключён: персональные данные не реплицируются за пределы
   домашнего региона; выносятся только обезличенные агрегаты.
8. **Проверки.** Регулярный внутренний аудит и проверки соответствия; фиксация изменений
   в архитектуре, влияющих на данные.

### Роли и доступ

| Роль | Доступ к данным |
|---|---|
| Пассажир, водитель | только свои данные в своём регионе |
| Оператор поддержки | данные своего региона, ограниченный набор полей |
| Бухгалтер | финансовые данные своего региона |
| Администратор | настройки без доступа к персональным данным |
| Партнёр | только свои агрегаты, без персональных данных |

## Альтернативы

| Альтернатива | Преимущества | Недостатки | Вердикт |
|---|---|---|---|
| Локальное хранение по странам (выбрано) | соответствует требованиям | дороже, сложнее | Принято |
| Единое центральное хранилище | простота и единый обзор | нарушает локальные требования | Отклонено |
| Вывоз данных с обезличиванием в центр | централизованная аналитика | риск несоответствия требованиям | Частично: вывозим только агрегаты |
| Отдельная система под каждую страну | максимальная изоляция | дорого и долго | Отложено |

## Недостатки, ограничения и риски

- **Стоимость и сложность** локальных регионов и интеграций; митигируется стандартизацией
  и единым слоем управления.
- **Нет единой картины по персональным данным всех стран** - аналитика работает на агрегатах.
- **Изменение законодательства**: требования меняются; нужен регулярный пересмотр стратегии
  и архитектуры.
- **Ограниченный режим** для пользователя при отказе домашнего региона: часть операций
  недоступна до восстановления (осознанное ограничение, см. ADR-003/ADR-004).
